# Week 4 Observation Report · Mining Data Streams

## Task 1 · Three Sketches (Bloom Filter, Flajolet-Martin, Reservoir Sampling)

- **Bloom Filter의 구조적 No False Negative 이유**:
  - 블룸 필터는 원소를 삽입할 때 $k$개의 해시 위치를 모두 1로 세팅하며, 비트를 0으로 되돌리는(clear) 연산이 존재하지 않습니다. 따라서 이미 삽입된 원소를 조회할 때 해당 $k$개의 비트는 반드시 모두 1로 남아있으므로 거짓 음성(False Negative)은 구조적으로 절대 발생할 수 없습니다.
- **거짓 양성(False Positive) 예측치 및 측정치**:
  - $m = 8,192$, $k = 5$, $n = 800$ 조건에서 이론적 예측치(교재 §4.4.2 공식)는 $P(FP) = (1 - e^{-k n / m})^k \approx 0.860\%$였으며, 20,000건의 미삽입 쿼리로 실측한 결과는 $0.820\%$로 이론치와 오차 범위 내에서 정확하게 일치했습니다.
- **Flajolet-Martin 결합 규칙 (Combining Rule)**:
  - 단일 평균은 극단적인 아웃라이어(큰 $2^R$)에 취약하고 단일 중앙값은 항상 2의 거듭제곱으로만 이산화되는 한계가 있어, 교재 §4.5.3에 따라 64개의 해시 함수를 8개 그룹(그룹당 8개)으로 묶어 그룹 내에서는 중앙값(Median)을 취하고 그룹 간에는 평균(Mean)을 취하는 Mean-of-Medians 방식을 채택했습니다. 여기에 보정 계수 $\phi \approx 0.77351$을 나누어 주어 2배 이내(1.23×)의 안정적인 고유 원소 수 추정치를 얻었습니다.
- **Reservoir Sampling 스트림 길이 불인지 보장 원리**:
  - 코드 상에서 `i`번째 원소(0-indexed, 현재까지 본 총 개수 $i+1$)가 들어올 때 `rng.randint(0, i) < k` 조건으로 저장소 진입 확률을 정확히 $k / (i + 1)$로 설정하고 기존 표본 중 균등하게 하나를 교체함으로써, 스트림의 전체 길이를 사전에 알지 못해도 매 순간 모든 원소가 동일한 확률 $k / n$으로 표본에 포함되도록 귀납적으로 보장합니다.

## Task 2 · Find Where Exact Stops Fitting

- **Exact 방식의 한계점과 병목 요인**:
  - $n = 6,400,000$에서 Exact set 방식의 메모리는 약 188.3 MB까지 선형적으로 증가했습니다. 반면 Flajolet-Martin의 메모리는 ~4.1 KB로 완벽히 평탄했으나, 64개 해시 연산 오버헤드로 인해 수행 시간이 약 1,525초(약 25분)에 달하여 CPU 시간(Time) 병목이 먼저 심각해져 추가 스트림 확장을 중단하였습니다.
- **메모리 증가율 비교 (Growth Rates)**:
  - Exact set 방식은 데이터 개수 $n$에 정비례하여 메모리가 $O(n)$으로 선형 증가(10만 개 시 3.9 MB $\rightarrow$ 640만 개 시 188.3 MB, 약 48배 팽창)했습니다. 반면 Flajolet-Martin 방식은 $n$이 64배 커지는 동안 메모리가 4,146 Bytes에서 4,150 Bytes로 거의 변함없이 유지되어 $O(1)$(실제 $O(k \log(\log N))$)의 일정한 메모리 공간 사용률을 명확히 입증했습니다.
- **고유 방문자 수 추정에 있어 2배 오차(Factor of two)의 적합성**:
  - **적합한 경우**: 대규모 웹 서비스의 트래픽 규모 파악(예: 일일 방문자가 수십만 단위인지, 수백만 단위인지 규모 파악 및 서버 용량 산정)이나 DDoS 공격 탐지와 같은 이상 트래픽 감지에서는 2배 이내의 추정치로도 충분히 의사결정이 가능합니다.
  - **부적합한 경우**: 광고 노출 과금, 정산 및 빌링(Billing) 시스템, 분기별 실적 공시와 같이 계약상 정확한 고유 사용자 수(Distinct Impression/User)를 기준으로 금전이 집행되는 도메인에서는 2배의 오차를 용납할 수 없습니다.

## Task 3 · Same Memory, Fewer Mistakes

- **파라미터 변경 및 최적값 유도 (Derivation)**:
  - 주어진 비트 수 $m = 80,000$, 삽입 개수 $n = 8,000$으로 원소당 비트 수 $m/n = 10$입니다.
  - 거짓 양성 확률 $f = (1 - e^{-k n / m})^k$를 최소화하기 위해 $k$에 대해 미분($\frac{df}{dk} = 0$)하면 최적 해시 함수 개수는 $k = \frac{m}{n} \ln 2 = 10 \times 0.69315 \approx 6.93$이 도출됩니다.
  - 따라서 $k = 7$로 설정하고, 1비트 대신 1바이트를 낭비하던 `bytearray(80000)` 구조를 1비트 단위 마스킹을 수행하는 `bytearray(10000)`(정확히 80,000 비트)로 패킹 구현하였습니다.
- **이론적 최소 바닥(Floor)과 달성 수치**:
  - $m/n = 10$일 때의 이론적 최소 거짓 양성률은 $f_{min} = (1/2)^k = (1/2)^{10 \ln 2} = (0.5)^{6.9315} \approx 0.819\%$ (~0.82%)입니다.
  - 개선된 `YourFilter`로 200,000건 질의를 측정한 결과, 기준선(NaiveFilter, 9.511%) 대비 오류율을 91.4% 감소시킨 **0.820%**를 기록하여 이론적 하한선(Floor)에 거의 오차 없이 도달했습니다.
- **스트림의 크기 $n$을 미리 알 수 없을 때의 대처 방안**:
  - $n$을 너무 작게 예측하면 스트림이 진행됨에 따라 비트 배열이 1로 포화되어 거짓 양성률이 급격히 치솟고 필터가 무용지물이 됩니다. 반대로 $n$을 너무 크게 잡으면 초기 메모리 공간을 과도하게 낭비하게 됩니다.
  - 따라서 실시간 스트림에서는 고정 크기 대신 **Scalable Bloom Filter(스케일러블 블룸 필터)** 기법을 사용하여, 필터의 채움 비율(Fill ratio)이 임계치에 도달할 때마다 이전 필터보다 비트 수가 크고 기하급수적으로 낮은 오류율을 갖는 새로운 블룸 필터를 직렬로 이어 붙여 확장하는 방식을 사용해야 합니다.
