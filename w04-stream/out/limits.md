## 3. 질문별 분석 및 답변

### A2. 실험 중단 지점과 병목 요인 (Time vs Memory)

- **대기 시간이 부담스러워지기 시작한 크기 및 최종 측정 지점**: n = 6,400,000. FM 수행 시간은 1,525.19초(약 25분 25초)였습니다. 이 크기부터 실험을 기다리는 시간이 개인적으로 부담스럽고 만족스럽지 않다고 느꼈으며, 이 크기까지 측정한 뒤 추가 확대 실험을 중단했습니다.
- **중단 이유**: 메모리 부족이 아니라, 현재 FM 구현의 긴 실행 시간으로 인한 실험 진행 부담이었습니다. 각 항목에 대해 64개의 SHA-256 해시를 계산하는 구현이므로, 작은 메모리를 사용하는 대신 상당한 계산 비용이 발생했습니다.
- **Exact set의 한계와 구분**: 같은 n = 6,400,000에서 Exact set은 약 11.809초, 최대 메모리 188,287,594바이트(179.56 MiB)였습니다. 이번 측정 범위에서는 Exact set이 메모리 부족이나 견디기 어려운 실행 시간에 도달했다는 증거는 없습니다. 따라서 이 중단 지점을 Exact set의 처리 한계로 해석하지 않습니다.
- **실험의 한계**: A2에서 요구한 '정확한 방식이 실제로 버거워지는 크기'는 이번 실험에서 확인하지 못했습니다. 측정하지 않은 더 큰 크기에서의 메모리 부족이나 스왑 발생을 결과로 주장하지 않으며, 정확한 방식의 한계를 확인하려면 추가 측정이 필요합니다.

### A4. 메모리 증가율 비교 (Growth Rates)

- **Exact Set**: 스트림 크기가 100,000에서 6,400,000으로 64배 증가하는 동안 최대 메모리는 3,925,620바이트에서 188,287,594바이트로 약 48배 증가했습니다. 저장하는 고유 원소 수에 비례하는 O(d) 공간을 사용하며, 이번 데이터에서는 고유 원소 수 d도 n에 거의 비례하므로 n에 대해 대체로 O(n) 증가를 보였습니다. 해시 테이블의 용량 확장과 객체 오버헤드 때문에 구간별 증가율이 정확히 동일하지는 않았습니다.
- **Flajolet-Martin**: 같은 범위에서 최대 메모리는 4,146바이트에서 4,150바이트로 4바이트만 증가했습니다. 이번 고정 해시 개수·고정 길이 해시 구현에서는 스트림 크기에 대해 사실상 O(1) 공간을 사용했습니다. 메모리는 전체 항목을 저장하는 대신 해시별 최대 trailing-zero 값과 관련 상태를 유지하는 데 사용됩니다.
- **해석**: 이번 구현에서 FM의 이점은 실행 속도가 아니라 작은 메모리 사용량이었습니다. 특히 n = 6,400,000에서 FM은 Exact set보다 메모리를 훨씬 적게 사용했지만 실행 시간은 훨씬 길었습니다. 작은 공간 복잡도가 곧 빠른 실행을 의미하지는 않았습니다.

### A5. Flajolet-Martin 정확도 비율 (Accuracy Ratio vs n)

- n = 100,000: **1.98×**
- n = 400,000: **1.73×**
- n = 1,600,000: **1.48×**
- n = 6,400,000: **1.44×**

모든 측정에서 추정값/실제값 비율이 0.5~2.0 범위에 들어왔으며, 실제 고유 개수를 과대 추정했습니다. 이번 고정 시드 실험에서는 n이 커질수록 비율이 1에 가까워지는 경향을 관찰했습니다. 다만 이 결과만으로 데이터가 커질수록 FM의 정확도가 일반적으로 좋아진다고 결론 내릴 수는 없습니다. 추정 정확도는 해시 결과와 결합 방식에 영향을 받으므로, 일반적인 경향을 확인하려면 여러 시드와 데이터 조건을 비교해야 합니다.
