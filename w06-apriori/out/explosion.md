## 3. 분석 및 핵심 질문 답변 (A2, A4, A5)

### A2 · 임계값이 감당하기 어려워진 지점과 가장 먼저 고갈된 자원
- **`support = 50` $\rightarrow$ `25` 구간에서 A-Priori의 1차 패스 필터링 능력이 완전히 고갈(Saturated)**되었습니다.
  - `support = 50`에서 이미 전체 2,000개 아이템 중 92.5%인 `1,849`개가 Pass 1을 통과하며, 피크 메모리가 `1.1 MB`(`support = 400`)에서 **`102.4 MB`로 약 93배 폭증**했습니다.
  - **`support = 25` 이하에서는 2,000개 아이템 전부가 최소 25번 이상 등장하여 Pass 1에서 단 한 개의 아이템도 걸러내지 못했습니다($|L_1| = 2,000$)**. 그 결과 A-Priori는 사실상 Brute-force 알고리즘으로 퇴화하여, 데이터셋에 존재하는 모든 고유 아이템 쌍(`893,456`개)을 전부 메모리에 카운터로 적재했으며 `support = 3`에서는 Python 힙 메모리가 **`156.6 MB`**, 실행 시간이 **`2.79s`**(초기 대비 6.5배)에 달했습니다.
  - 만약 전체 아이템 수 $N$이 2,000개가 아니라 실제 대형 마트 수준인 $100,000$개였다면, 이 지점에서 $\binom{100,000}{2} \approx 5 \times 10^9$개의 카운터(수백 GB)가 생성되어 **RAM(메모리)**이 가장 먼저 고갈(OOM)되었을 것입니다.

### A4 · 지지도 반감(Halving)에 따른 카운터 수의 비선형 성장률
- 아이템 카탈로그가 포화되기 전인 `support = 400 -> 200 -> 100 -> 50` 구간에서 지지도를 절반으로 낮출 때마다 `peak_counters`는 단순히 2배(Doubling)가 되는 것이 아니라 각각 **`5.54배` (`10,585` $\to$ `58,626`) $\to$ `4.67배` (`58,626` $\to$ `273,701`) $\to$ `3.00배` (`273,701` $\to$ `820,259`)**로 **2배보다 훨씬 가파른 초선형/이차(Super-linear / Quadratic) 폭발**을 보였습니다.
- **원인**: 아이템 빈도가 Zipf 분포($w_i \propto i^{-0.8}$)를 따르기 때문에 지지도를 절반으로 낮추면 생존 단일 아이템 수 $|L_1|$이 약 `2.36~2.39배` 증가하는데, Pass 2의 후보 쌍 개수는 $\binom{|L_1|}{2} = \frac{|L_1|(|L_1|-1)}{2} = \mathcal{O}(|L_1|^2)$로 **생존 아이템 수의 제곱에 비례**하기 때문입니다($(2.38)^2 \approx 5.66$배).

### A5 · 빈발 쌍(정답) 증가율과 카운터 증가율의 괴리(Gap)가 의미하는 바
```
Support:   400 ──────► 200 ──────► 100 ──────► 50
Answers:   249         776        2,244       6,397     (총 25.7배 증가)
Counters:  10,585     58,626     273,701     820,259    (총 77.5배 증가 — 정답1개당 128개 카운터!)
```
- `support = 400`에서 `50`으로 낮추는 동안 우리가 얻고자 하는 **실제 빈발 쌍(정답)은 `249`개에서 `6,397`개로 약 `25.7배` 완만하게 증가**한 반면, 이를 찾기 위해 메모리에 유지해야 하는 **쌍 카운터(`peak_counters`)는 `10,585`개에서 `820,259`개로 약 `77.5배` 폭증**했습니다.
- `support = 50` 시점에는 **정답 1개를 찾기 위해 평균 128.2개의 카운터(`820,259 / 6,397`, 99.2%가 최종 탈락할 쓰레기 후보 쌍)**를 메모리에 들고 있어야 합니다.
- 즉, 실무에서 누군가 *"흥미로운 롱테일 규칙을 조금만 더 보고 싶으니 지지도 임계값을 살짝만 낮추자"*라고 요구할 때, 얻게 되는 결과물(정답)은 조금 늘어나지만 **메모리 비용은 생존 아이템 수의 제곱($\mathcal{O}(|L_1|^2)$)으로 폭발**하여 시스템 메모리를 멈추게 만든다는 것이 A-Priori Pass 2의 핵심 병목이며, 이를 해결하기 위해 Task 3의 **PCY 알고리즘**이 등장합니다.
